# NetMap — Network Discovery Dashboard

NetMap is a real-scan-only Streamlit application for reviewing saved Nmap XML, comparing two real scans, and exporting CSV/HTML reports. It never starts a network scan. The current light slate-and-blue interface is retained.

## Launch on Windows

Open PowerShell in this project folder and run:

```powershell
py -m pip install -r requirements.txt
py -m streamlit run dashboard.py
```

You can also double-click `Run-Demo.bat` (legacy launcher filename); it now only starts the application and does not generate demo data. On each new session, NetMap first asks you to select a valid Nmap XML scan from `scans/` or upload one. The dashboard appears only after successful validation and loading. Use **Change scan** in the sidebar to return to the input screen.

## Use the application

- **Overview** shows metrics, chart, host/port records, and exports for the one currently loaded scan.
- **Host Discovery**, **Ports & Services**, and **Reports & Exports** use that same loaded scan; they do not offer independent data sources.
- **Comparison** requires two valid real Nmap XML scans. Select both from `scans/` or upload separate Baseline and After files.
- If there is no scan in the new session, no metrics or sample data are shown. Invalid XML is rejected. Valid empty scans show empty states.

Fixtures under `sample_data/` remain for automated parser/report tests only. The production dashboard does not load or display them. Existing `outputs/demo-*` files, if present from an earlier version, are not read or generated by the current app.

## Existing saved scans

The project contains `scans/live_scan.xml` and `scans/live_scan_after.xml`, along with matching Nmap text outputs. Each saved scan reports one host up, 96 closed and four open TCP ports among the 100 common ports scanned: 135, 139, 445 and 8080. Both record target `172.17.104.158` and Nmap 7.80. The pair has no differences in detected open endpoints or service labels. Nmap's port 8080 product label is a fingerprint, not definitive proof that Oracle software is installed. An open Windows networking port alone does not prove a vulnerability.

CLI-generated review files already present under `outputs/` are from these saved scans: `live_scan_report.csv`, `live_scan_hosts.csv`, `live_scan_report.html`, `live_scan_comparison.csv`, and `live_scan_comparison.html`. The app generates downloads only from the currently loaded scan or the two selected comparison scans.

## Existing packet capture

`scans/nmap_scan_capture.pcapng` is readable by the installed `tshark` utility and contains 94 packets over about 45 seconds. Its capture time falls between the saved scans. The broad filter `ip.addr == 172.17.104.158 && tcp.flags.syn == 1 && tcp.flags.ack == 0` matches six ICMP host-unreachable messages with quoted SYNs to unrelated hosts on port 7680. A direct SYN filter for the saved scan target ports 135/139/445/8080 returns no frames. This capture does not corroborate the saved scan port results. No screenshot or firewall/VM experiment is claimed.
